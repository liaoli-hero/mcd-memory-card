### 2.2 参赛资格

- 中国大陆地区合法居民；
- 年龄 ≥ 18 周岁，或未满 18 周岁但已获父母/法定监护人同意；

- 同一 GitHub 账号 / 麦当劳账号 / 手机号 / 设备号 / IP 视为同一用户；
- 同一 GitHub 账号有多个参赛项目时，**仅 Star 最高的一个进入排行榜**。

### 2.3 提交材料

项目须为 **GitHub 公开仓库（Public）**，**创建时间在 2025-12-25 00:00 至 2026-10-25 23:59 之间**。

| 文件名 | 说明 | 是否必须 | 可改性 |
|---|---|---|---|
| `README.md` | 项目介绍、安装方法、使用示例、目标用户 | 必须 | 文件名不可改 |
| `CONTEST_DECLARATION.md` | 参赛声明，**须直接用官方模板，内容不可改** | 必须 | **文件名与内容均不可改** |
| `MCP_INTEGRATION.md` | 实际使用的 MCP Server、Tool、调用流程、业务价值 | 必须 | 文件名不可改 |
| `mcp-config.example.json` | 脱敏配置示例，**只允许环境变量占位符** | 必须 | — |
| `workbuddy.md` | WorkBuddy 对话上下文 | 参加 WorkBuddy 专项奖励时必须 | 文件名不可改 |
| 源代码 | 项目主体，形式不限 | 必须 | — |

> 官方 README 表格只列 5 项，`activityGuidelines.md` 列 6 项（多 `mcp-config.example.json`）。**以 activityGuidelines.md 为准，两个都放。**

**报名 Issue 格式**（正文 ≤ 1000 字、禁带图片）：

```text
【参赛申请】
项目名称：{项目名称}
项目地址：{项目 GitHub 仓库地址}
项目简介：{项目简介}
```

报名成功 / 失败均由系统在 Issue 下回复；失败可按原因修改后重新提交。

### 2.4 评选标准

**唯一量化硬指标是 GitHub 公开 Star 数**，无作品质量评审环节：

- 定时采集报名成功项目的公开 Star；
- **Star = 0 的项目不进排行榜**；
- 原则上前 100 个项目进入排行榜；第 100 名并列同分时，所有并列项目一并进入（入榜数可能 > 100）；
- 并列排名占用名次并顺延奖励（例：1、1、1、4、5）；
- **活动开始前已获得的 Star 也计入**；
- 刷 Star、多账号、脚本刷榜等一律取消资格。

> ⚠️ **v1 表述更正**：`Star > 0` 仅是 **进入排行榜的必要条件**，不等于获奖。最终仍须：
> ① 在 10-26 00:00 采集时排名进入前 100（含并列）；
> ② 通过麦当劳的参赛资格与获奖资格审核（身份、原创性、内容合规、无刷榜）。
> 两个条件任一不满足即不在获奖范围。

## 5. 选题调整：暂定方向「麦门回忆卡」

### 5.1 原方向作废说明

v1 推荐的「麦门年报 McWrapped」依赖**年度**口径，而 `order-list` 无年度承诺，**该前提不成立，作废**。

### 5.2 调整后方向

**「麦门回忆卡」**——不承诺"年度"，只呈现**实际可取得的真实日期区间**，并**显式标注覆盖范围**。

三条硬性设计红线（不可违反）：

1. **只统计真实可获取的日期区间**，界面必须明写"本次覆盖：YYYY-MM-DD 至 YYYY-MM-DD（共 N 天 / N 单）"；
2. **不宣称"吃掉了什么"** —— 只能说"订单记录中出现的餐品"，且区分"记录到"与"实际食用"；
3. **不把消费记录折算成个人实际摄入** —— 营养数据仅标注为"该餐品官方标注值"，明确声明不等于本人摄入量。

MVP 可行性结论见独立文档：`麦当劳开发大赛_麦门回忆卡_MVP方案.md`。
