# 演示截图方案

本方案面向 GitHub 首次访问者：先看清作品输出，再通过三种场景理解“数据有边界”。画面沿用现有米色底、红色强调和卡片布局，使用真实运行截图，不制作不存在功能的效果图。

## 已交付截图

所有图片均来自本次改进后的根目录 `index.html`，通过本地 HTTP 服务读取仓库自带的虚构 JSON；没有调用真实账户或麦当劳服务，没有修改任何示例数值。

|---|---|---|

README 首图显示宽度 640；两张窄屏图并列放在场景说明后。避免堆放整页长图，让访客先看见三个核心卡片。

## 复拍步骤

1. 在仓库根目录运行 `python -m http.server 8000 --bind 127.0.0.1`。
2. 使用新的浏览器页面，缩放为 100%，打开 `http://127.0.0.1:8000/index.html?data=full`。
3. 首图使用 960 CSS 像素宽视口；部分与无订单场景使用 390 CSS 像素宽视口。切换场景后等数据与动画完成。
4. 从页面顶部拍到第三张卡片下方。保留该卡的范围说明，避免切断卡片；不必截入第四张卡。
5. 输出 PNG，覆盖上表文件。实际交付尺寸以图片文件为准；若字体或浏览器变化，按卡片边界调整高度。
6. 对照源 JSON 与截图，确认当前选中的场景、数值、未知项与范围一致。README 同时保留“纯虚构”图注。

双击文件也能试玩，但会触发精简的内嵌样例；为了让截图与 `samples/` 可逐项对照，复拍使用 HTTP 模式。

## 真实性与发布边界

- 不隐藏或裁去“示例数据 / 非真实账户 / 虚构演示”横幅；打印分享同样保留标记。
- `fictional-full` 只表示演示信息较齐，不表示真实接口已验证可以取全历史。虚构的 3 页与时间跨度不能当作接口能力证明。
- `source.tools` 和工具失败原因也属于虚构场景设定，不是本次网络调用日志。
- 无订单记录不能解读为用户从未消费；只有确认为 0 的字段显示 0。
- 不使用真实账户、订单号、门店行踪、券码、二维码、Token、头像或私人文件名作为公开截图素材。
- 如需展示真实接入证据，应另用脱敏的调用说明，明确时间与验证范围，参见 `MCP_INTEGRATION.md`。不将其混入演示图。
- 不添加“官方出品”“已获奖”“完整年度账单”等未经证实的标语。自愿 Star 的文案只出现一次，不用遮罩、倒计时、奖励或弹窗催促。
